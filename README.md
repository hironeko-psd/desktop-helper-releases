# DesktopHelper

Windows 10 / Windows 11 64 位桌面工具的正式版本与更新文件。

## 获取版本

[前往最新版发行页](https://github.com/hironeko-psd/desktop-helper-releases/releases/latest)

检查更新和下载公开附件不需要 GitHub 账号。首次使用可下载 `DesktopHelper-版本号-Setup.exe` 安装，运行组件已包含；已安装用户优先使用程序内“检查更新”。其他更新附件由程序处理，无需手动解压覆盖安装目录。

安装包目前没有 Windows 发行者 Authenticode 签名；应用更新使用内置 Ed25519 公钥验证，并检查更新包大小与 SHA-256。

## 1.0.10 更新内容（已发布）

[1.0.10正式发行](https://github.com/hironeko-psd/desktop-helper-releases/releases/tag/v1.0.10)已公开，本地验收和匿名网络验证均已完成：31组394项源码回归通过，另有实际发行字节码与运行库154项验证通过，两组证据分别记录，不合计为548项；完整隔离安装及1.0.8／1.0.9原生升级也已通过。发布时 latest 确认为1.0.10，匿名 Ed25519 验签、五附件实际大小与摘要、发行代码调用 Windows 原生 HTTPS 下载均通过；以后可下载版本以最新正式发行页为准。

- **更新连接的有限恢复**：为更新检查和下载遇到超时、连接中断时增加有限恢复。始终请求同一 URL，沿用系统自动代理和 TLS 校验；一次 urllib 请求后最多两次 Windows 原生 HTTPS 尝试，共用总截止预算，重试不重新计时。证书、更新签名、大小与摘要验证继续保留，不保证任何网络环境均可连接。
- **聊天入口复核**：原像素复核未通过、但按钮和保护检查通过时，尝试有界的局部文字准备与新帧完整复核。只有最新画面的身份、文字、几何位置、按钮和保护检查全部通过，才允许后续操作；不会模糊合并发送者，也不会在暂停或超时后授权点击。本地源码及发行代码验证已完成，不放宽地图入口或申请确认检查；现有诊断缺少真实失败前后配对，尚未证明已逐帧修复用户现场问题，本机模拟采集与时钟也不代表队友电脑实测。
本次两包来自画面1440×3440的队友1，涉及更新12002与聊天标题／位置复核拒绝；识别速度慢的反馈来自另一位队友2。单轮日志耗时不等于队友1电脑慢，两阶段时效优化是保守设计，不是现场根因证明。

- **保留既有保护**：沿用 CPU 稳定识别路径和 DirectML 禁用方案；不新增 GPU 启用、镜像更新源或修复工具。

旧版更新器无法取得修复代码时，需要由喵喵另行提供已正式发布的完整离线安装包作为绕过旧更新器的途径。正常退出助手后在原位置安装，保留设置与申请历史；1.0.10完整安装包已在上述正式发行页提供。

## 1.0.9 历史更新内容

以下为 1.0.9 发行定稿说明，当前实际可下载版本以最新正式发行页为准。

- **原始截图超时恢复**：原始截图（raw screencap）超时后切换到 PNG 截图，丢弃失败的这一轮，下一轮取得新的 PNG 画面后再识别。避免一次原始截图超时就被当作连接中断而停止任务。
- **保留操作保护**：恢复不会重放旧点击或沿用旧坐标，不解除用户手动暂停，也不重置申请策略和待确认记录。PNG 截图仍失败时会停止，不在缺少新画面的情况下继续操作。
- **范围限定**：本次只修复截图恢复，沿用1.0.8的 CPU 稳定识别路径，DirectML 仍暂时禁用；不包含新的 GPU 启用或识别算法改造。

## 1.0.8 历史更新内容

以下为 1.0.8 发行定稿说明，当前实际可下载版本以最新正式发行页为准。

- **姓名复核**：队长昵称从首位成员区域单独读取并有限复核，减少位置变化、相邻成员连读和低可信初读造成的误停。真实不同姓名及证据不足仍会拦截，不模糊合并身份。
- **历史去重**：修复旧“已开战／已过期”非申请观测阻挡后续明确可申请队伍的问题。已申请、结果未确认、观察到已申请及人工“不再申请”的记录继续受保护，不清空历史绕过防重复。
- **慢电脑与动态画面**：优化慢截图、慢识别和慢磁盘后的重新核验，按动作检查按钮、身份与页面，减少公告、头像、角标等无关变化造成的误拦。新复核帧按实际截图耗时适配安全时限，旧 OCR 坐标不会因此延长有效期；目标变化、过期画面或证据不足时不强行点击。持续卡顿或反复无法安全操作时会明确暂停。
- **申请归因**：“助手确认申请”只统计匹配的已保存申请意图、执行回执和后续申请结果。另列“观察到已申请”和旧版无法归因的确认记录，两者不计入助手成功；进入队伍、列表处理完成或输入已发送也不代表申请成功。
- **停止与诊断**：日志说明未执行、停止和返回失败的具体原因。最近8条关键策略停机证据元数据单独留在本次运行内存，不额外默存游戏图；主动开启画面保留后，才会在最近30秒缓存之外额外限量保留最多3对复核失败前后图。图片受频率、容量与编码限制，导出时仍需单独勾选；关闭保留开关清空图片缓存，重启清空内存记录，诊断不自动上传。

**本版使用 CPU 稳定识别，暂时禁用 DirectML 显卡文字识别。** 验证已复现特定调用顺序下的 DirectML 原生崩溃，因此“自动”和“优先 GPU”设置均实际使用 CPU，原有偏好仍保存。局部文字识别和动作复核优化继续启用。这是稳定性取舍，不表示 GPU 崩溃根因已彻底修复，也不保证任意硬件、持续卡顿或所有游戏画面均可自动执行。

## 应用内更新与旧版证书问题

**已安装 1.0.7、1.0.8 或 1.0.9**：使用程序内“检查更新”，下载和校验完成后暂停任务并应用更新；也可退出助手后在原位置运行新版安装包。设置和申请历史保留，无需先卸载。更新后需自行重新开始任务。

**仍在 1.0.6 且因证书错误无法更新**：向喵喵获取“小型更新修复工具（1.0.6 → 1.0.8）”，正常退出助手后按工具提示操作；也可使用完整安装包原位升级。该工具仍严格用于 1.0.6 → 1.0.8，固定官方 1.0.8 清单及更新包 URL，不随 `latest` 转向其他版本，并保留 HTTPS、签名、大小、SHA-256 和版本检查。成功升级到1.0.8后，可通过程序内“检查更新”继续升级到已正式发布的新版；若仍无法连接，请获取完整离线安装包。它仍只用于1.0.6 → 1.0.8，不是1.0.6 → 1.0.9或1.0.10工具；旧的1.0.6 → 1.0.7工具也不能代替它。

小工具由喵喵单独交付，不作为第六个正式发行附件上传。用户需要接收并启动一次；新清单不会自动修复旧进程，也不意味着旧版“检查更新”按钮已经自行恢复。升级后继续使用程序内更新，保留 Windows 原生 TLS 兼容、证书验证、更新签名与失败回滚；无需 GitHub 账号，不要关闭证书验证。

## 连接和诊断

首次使用先打开 MuMu 和游戏，再在助手设置中检测并选择所需设备。设备需要开启并允许 ADB 调试连接。检测采用 ADB 已登记设备和 MuMu 官方实例信息，不扫描局域网或任意未知服务，连接后不会自动开始申请。

诊断文字尽力脱敏，游戏截图不会自动脱敏；分享前请检查玩家名字和聊天内容。输入已发送不等于游戏已经接受申请，结果以游戏反馈及申请记录为准。已发出的游戏申请不会因暂停或关闭助手而撤销。
